# desktop spec (screen corners) · shell-engineer · M2

UI naming (renamed 2026-10-18, owner decision): internally `hotCorners` / `HotCorner*.qml`; the user sees "Screen Corners" (fr « Coins de l’écran »).

## macOS reference behavior (described in words, no Apple images committed)
Not yet measured (F1 pending). Assumed: moving the pointer into a screen corner and resting there for a short moment triggers a user-chosen action (Mission Control, Notifications panel, Launchpad, lock screen); each of the four corners is configured separately and "none" disables it.

## Purpose and non-goals
Screen Corners on every screen, configured in `grassfield.json`. Non-goals now: a Settings UI to choose the actions (the keys are written by `Settings.setHotCorner`, a UI comes with Settings, M4), modifier keys that must be held, corner animations. The wallpaper (`Wallpaper.qml`) is documented in `ui.md`.

## Functional requirements
1. Per screen and corner one layer-shell window (`HotCorner.qml`), namespace `grassfield-hotcorner`, layer Overlay (reachable above fullscreen apps), anchored to the corner, `Tokens.hotCornerSize` (2 px) square, transparent, exclusion mode Ignore (no exclusive zone), keyboard focus None. A corner whose action is `none` is not mapped at all.
2. Dwell: `DwellGate` fires once, `Tokens.hotCornerDwellMs` (150 ms) after the pointer entered the corner window; leaving earlier cancels it; after firing the gate stays latched until the pointer is proven to have left (macOS: once per entry, never again while the pointer rests). The corner window never grows (it would steal clicks from the menu button): `PointerTracker` (`services/`) receives pointer positions from HoverHandlers on the menu bar, the wallpaper and the Dock, and a reported position more than 8 px from the corner re-arms; so does a corner hover exit while no full-attention shell surface (the FocusReturn holders: Apps, Overview, Search, menus, the switcher, the Notification Center) and no session lock is up, since only the pointer itself can have moved out then. While one is up, a hover exit may be that surface covering the corner (however late it maps) or a real leave (the Notification Center and Search leave the menu-bar strip, and so the top corners, uncovered): the corner asks the compositor where the pointer is (`hyprctl cursorpos`, read only, once) and re-arms when it is more than 8 px away; it asks again when the last such surface closes while the corner window is not hovered. No timing is involved. While the session is locked no corner fires. Closing Overview or Apps with the pointer still in the corner therefore does not reopen it, while leaving and jumping straight back re-fires. No firing while the target surface is open (notifications).
3. Actions (`HotCornerActions.js`, pure): `none`, `overview` (`qs ipc call overview toggle`), `notifications` (in-process `Notifications.toggleCenter(screen)` with the corner's output, so the Notifications panel opens on the screen that fired), `lock` (`lock lock`), `apps` (`apps toggle`). Calls go through `qs ipc --pid <this shell>` so surfaces stay decoupled. `apps` is the future Apps/Launchpad surface: `qs ipc show` is read first and the call is made only when the target `apps` exists, otherwise nothing happens.
4. Settings: `hotCorners.topLeft|topRight|bottomLeft|bottomRight`, enum `none|overview|notifications|apps|lock`, default `none` (`config/schema/grassfield.schema.json`). `SettingsStore` clamps unknown values to `none`; `Settings.hotCorner*` read, `Settings.setHotCorner(corner, action)` writes. Edits to the file apply live (the store watches it).
5. Click safety: the 2 px corner windows never overlap a control. The menu bar buttons start `spacingXs` px from the screen edge (the Grassfield menu at the left, the clock at the right) and the Dock is centered, so a click in the very corner pixel hits nothing clickable. If a future control sits in a corner, move it inward instead of changing this window.

## Acceptance criteria
- `tests/unit/tst_hotcorners.qml`: dwell fires after the interval, cancels on leave, fires once per visit, token is 150, actions clamp to the enum, IPC argv, apps target detection (L0).
- Nested screenshot with `hotCorners.topLeft = "overview"` and the real pointer moved to the corner: Overview opens (L2, `.dev/shots/hotcorner.png`).

## Interfaces / contracts (versions)
`grassfield.json` contract version 1 keys above; reads `Settings`; calls the IPC targets `overview`, `notifications`, `lock`, `apps`.

## Dependencies (verified versions)
Quickshell 0.3.1: PanelWindow, WlrLayershell, HoverHandler, Process, `Quickshell.processId`, `qs ipc`.

## Degraded behavior
Unknown config value: `none`. Target surface missing (`apps`): no-op. No compositor plugin needed.

## Automated tests · Manual verification steps
`scripts/dev/test.sh`. Manual: set `"hotCorners":{"topLeft":"overview"}` in `.dev/config/grassfield.json`, nested-up, `scripts/dev/pointer.sh output GF-REF abs 400 400 sleep 300 abs 0 0 sleep 900`, `shot.sh`.

## Performance · Accessibility · i18n
No timers run until the pointer is in a corner. Corners are pointer-only; every action has a keyboard path (CTRL+UP Overview, SUPER+N Notifications panel, SUPER+CTRL+Q lock). No user-visible strings.

## Startup

The session's entrance (ADR-0040 step 6, ID-20): the wallpaper maps first with its own first frame; the desktop icons, the menu bar and the Dock then fade in together (`session.revealMs`) once all are final, or after `session.revealTimeoutMs` (`shell/services/Entrance.qml`; the icons say `icons:<output>` is ready when `ready` holds). Measured by `tests/visual/appear-once.sh` from the journal lines of `shell/services/Journal.qml`.

The desktop exposes nothing before its first layout is final (`Logic.settledOn`): the surface is sized, the settings file, the widgets file and the positions file were read, and the first complete listing of the resolved folder is in. `lay` stays empty until then, so no icon appears at a default slot and then moves, and no partial listing is shown and then pruned. The folder model starts on the process's working directory (often the home folder) before its folder is set: a row whose parent is not the desktop folder is a stale row, the listing is refused and nothing is pruned. Clean Up and Clean Up By do nothing before the desktop is ready (they would save empty positions). Each icon stays invisible until its image is in and, for a launcher, its file is read, bounded by `desktopIcon.loadTimeout` (macOS shows each icon whole).

## Known limitations
- A real pointer is clamped to the output edge, so a corner is reached only on an edge shared with the screen boundary; with side-by-side outputs, the inner corners are not at the pointer's stop and still work only where the pointer can reach them.
- The Overlay-layer corner windows cover the 2 px corner of the Quick Settings/popup overlay and of fullscreen apps by design.
- The `apps` IPC target name (`apps`, function `toggle`) is an assumption until the Apps surface exists.
- Full-screen windows (macOS: hot corners work over full-screen apps too): the corner windows are on the Overlay layer, above them, so a corner fires over a full-screen window; and since no shell surface is visible there to report the pointer, the corner re-arms from the compositor's pointer position (asked when the surface the corner opened closes, or on a hover exit while one is up), never from the menu bar, wallpaper or Dock alone.

# Desktop icons v1 · shell-engineer

## macOS reference behavior (words)
The desktop shows the files and folders of the Desktop folder as large icons with wrapped labels (two lines at most; white with a soft dark halo, or black without it where the wallpaper under the label is at least `menubar.toneLightBelow`, the menu bar's rule, read from the wallpaper's luminance grid: ADR-0039 step 25, `IconsLogic.darkLabelOver`), highlighted when selected, arranged in columns from the top-right corner. Dragging on empty space draws a selection rectangle, a double click opens, icons can be dragged to rearrange (positions are remembered), onto the Dock Trash to trash them, and into or out of applications. The context menu of empty space offers New Folder, Paste Item(s) when the clipboard holds files (copies; items cut in Files, Dolphin or Nautilus are moved with `mv --update=none-fail --no-target-directory`, which never replaces a name, even a hidden file's, and the clipboard is emptied once one of them has moved; a path with `.` or `..` segments is refused: `IconsLogic.parseClipboardProbe` reads KDE's `application/x-kde-cutselection` or GNOME's `x-special/gnome-copied-files`), Get Info (of the Desktop folder), Change Wallpaper…, Edit Widgets…, Clean Up and Clean Up By ▸ (Name, Kind, Date Modified, Date Created, Size); the one of a selection offers Open, Open With ▸ (the default application first), Move to Trash, Get Info, Rename, Compress, Duplicate, Make Alias, Glance and Copy, with right-aligned shortcut hints.

## Functional requirements
1. Surface: `DesktopIcons.qml` maps one layer-shell window per screen, always (also with `desktop.showIcons` off, as macOS keeps its desktop menu when the items are hidden); only the primary screen (the main display, `MainDisplay.screenName`, ADR-0044: the choice in Settings > Displays, else the built-in panel, else the first screen; the dev override `GRASSFIELD_DESKTOP_SCREEN=<output>` is read there, once) shows the icons (`iconsHere`: the primary screen with `desktop.showIcons` on), the other screens have the bare-desktop menu and the rubber band only, so a right click on the empty desktop of any display opens the menu. One `DesktopFiles` serves every screen (the folder, the slots, the file operations are the primary's). Menu on a screen without the icons: no Clean Up / Clean Up By (nothing there to arrange), and with the items hidden also no New Folder / Paste; drops and the file keys are off there. Namespace `grassfield-desktop-icons`, Background layer, created after the wallpaper (so above it) and below the Bottom-layer widgets surface (`DesktopWidgets.qml`, not touched). The window spans the screen and has no input mask: a click on empty desktop starts a rubber band and gives the desktop the keyboard (see "Keyboard focus" below). The widgets layer above keeps its own input. It reports the pointer to `PointerTracker` (the wallpaper below no longer sees it). Nothing animates or repaints on a timer.
2. Folder: `$GRASSFIELD_DESKTOP_DIR`; else, in a dev session (`GRASSFIELD_DEV=1`), `<state>/desktop-sandbox`; else `xdg-user-dir DESKTOP`; else `~/Desktop` (also when XDG answers `$HOME`). `scripts/dev/shell-run.sh` always passes `GRASSFIELD_DESKTOP_DIR` (default `.dev/desktop-sandbox`). Model: `Qt.labs.folderlistmodel` (hidden files are not shown). The folder is never created or modified except by explicit user actions below.
3. Grid (`IconsLogic.js`, pure): slot (col, row), col 0 right-most. Unplaced icons take the first free slot column-first from the top-right, in case-insensitive name order. Cell, margins and sizes are tokens (`desktopIcon*`); the grid avoids the menu bar and the Dock footprint.
4. Icons: theme icon from an extension map (fallback `text-x-generic`), images show a thumbnail with `sourceSize` capped at `desktopIconThumbnailMax`. A `.desktop` file shows its `Name` and `Icon` as plain text (parsed, never executed).
5. Interaction: click selects (Ctrl toggles, Shift adds; a press on an icon that is already part of a multi-selection keeps the selection for a group drag, and the release without drag then leaves that icon alone selected, as in macOS); rubber band on empty space; double click opens; icons can be dragged. Keyboard, active ONLY while the desktop surface holds the keyboard ("Keyboard focus" below): arrows move the selection, Return (or F2) renames the selected file, Ctrl or Meta+O opens the selection, Ctrl+Backspace moves it to the Trash, Ctrl+A selects all, Ctrl+I shows Get Info of the selection (of the Desktop folder when nothing is selected), Ctrl+D duplicates it, Ctrl+C copies it, Ctrl+V pastes the files on the clipboard, Space shows Glance for the selection (`grassfield-preview --glance`, `shell/services/GlanceApp.qml`, dev override `GRASSFIELD_PREVIEW_CMD`, passed by `scripts/dev/shell-run.sh`; Space again closes it), Esc closes Glance, else clears the selection. The context menus (`IconMenu`, `PopupMenu`) are a `PopupWindow` anchored to the desktop surface with a keyboard grab (`IconsView.qml`): it draws above windows, takes the keyboard, and a click elsewhere dismisses it (the compositor swallows that click, as macOS). The window grows to the menu's `extent` (the menu and its open submenu) and blurs both; Hyprland blurs a popup of the icons layer only through the layer rule `gf-desktop-menu-blur` (`blur_popups`), not through `BackgroundEffect` alone. Menu actions: Get Info runs `grassfield-files --info` (only the Get Info window of each item); Change Wallpaper… opens Settings on the Wallpaper pane; Edit Widgets… opens the widget gallery; Compress makes `<name>.zip` (several items: `Archive.zip`) with `bsdtar`; Duplicate makes `<name> copy` (before the extension: `Report copy.md`); Make Alias makes a symbolic link `<name> alias`; Paste copies the clipboard's files (`text/uri-list`) in, or duplicates those already on the desktop; Icons always snap to the grid (macOS Sort By > Snap to Grid, on and not switchable: a slot is a whole cell, a drop or a move lands on the nearest free cell, `IconsLogic.slotAt` / `nearestFree` / `moveGroup`); Sort By, Use Stacks and Show View Options have nothing behind them and are not offered. Clean Up packs the icons into the grid in their visual order, Clean Up By in the chosen order (dates newest first, size largest first). Open With lists the applications of the selection's common types (`dock/file-types.sh`, `xdg-mime query default`); an answer for an older selection is dropped.
   Rename: an in-surface `TextInput` (`DesktopIcon.qml`), light field (`color.fieldFill` at `desktopIcon.renameFillOpacity`) with dark text (`color.fieldText`, role "rename field text" in `tests/visual/contrast-roles.json`, gate A2) and an accent selection. Return commits (also an Enter), Esc cancels, a click elsewhere on the desktop, or the field losing the keyboard (a click on a window, the other output), commits as in macOS (a name that cannot be used cancels then; with Return it stays open with the reason). The field is `enabled` only while its icon is renaming, so a finished rename can never hand focus back to a hidden field, and `accepted` is ignored unless the field is visible (`tests/shell/desktop_rename_focus`).
   Widgets: slots whose cell overlaps a desktop widget tile of the same screen (`Widgets.desktop`) are not available to icons (`Logic.blockedSlots`); icons on such slots move to the next free slot. Widgets win: they never reserve cells, they only block them.
6. File operations, only on those user actions and always as one argv: `gio trash`, `gio move --no-target-directory -- <src> <dest>` (rename; `gio rename` would read a name starting with `-` as an option), `gio mkdir -p`, `gio move`, `cp -a --no-clobber` (copy; `gio copy` refuses directories), `gio open`, `wl-copy --type text/uri-list` (Copy). Rename validation: not empty, no `/`, not `.`/`..`, no control characters, at most 255 bytes, never an existing name (a refused name keeps the field open with a red border and a short reason under it; a rename the file system refuses reopens the field with "Rename failed"). New Folder creates `untitled folder` (numbered) and opens its rename field. `.desktop` files are opened as text in the default text editor (`gio mime text/plain` then `gtk-launch`), never executed: the GNOME trust model (`metadata::trusted`) is not implemented.
7. Positions: `desktop-icons.json` in `$GRASSFIELD_STATE_HOME` (dev) or `$XDG_STATE_HOME/grassfield`, version 1, keyed by file name, directory 0700, file 0600, atomic write, debounced. Names that no longer exist are pruned (only once the folder model is ready, and not for names with an operation in flight). A rename keeps the position. A broken file is copied to `.bak`.
8. Drag and drop (real `wl_data_device` drags through Qt `Drag.Automatic`, mime `text/uri-list` plus the marker `application/x-grassfield-desktop-icons`): a drop on the desktop with the marker rearranges (group keeps its shape, occupied slots resolve to the nearest free one); other `text/uri-list` drops are copied into the desktop folder under unclaimed names and placed at the drop point; a drop on the Dock Trash tile (`shell/dock/Dock.qml`, highlighted while hovered) runs `gio trash`.
9. Setting `desktop.showIcons` (bool, default true; schema, defaults, `Settings.desktopShowIcons`, `Settings.setDesktopShowIcons`; the Settings app rule list in `apps/settings/qml/Store.js` mirrors it).

## Known limitations
- Icons appear on the first screen only. Positions are slots, so a smaller grid re-places icons.
- Drops from other applications always copy: Qt does not tell Shift (move) from the default action. Not exercised with a real foreign source (no DnD source app in the nested session); the drop path is the same code as the internal one.
- Use Stacks, Show View Options (icon size, a kept sort order) and mounted-volume icons are omitted. Rename is off for several items (macOS opens a batch rename window; there is none). Copy and Paste carry files only (`text/uri-list`).
- Because the surface takes the whole screen, windows that are unmapped leave the empty desktop owned by the icons surface, not the wallpaper (the wallpaper has no input of its own).

## Wallpaper (ADR-0016)
`Wallpaper.qml` maps one Background-layer window per screen (namespace `grassfield-wallpaper`). Each output has a `WallpaperFeed` (`shell/desktop/WallpaperFeed.qml`) that turns the `wallpaper` settings (`WallpaperConfig.resolve`, per-display overrides included) into what to draw:
- `builtin`: the artwork (`WallpaperArt`, drawn by `ui/Grassfield/Ui/GrassfieldArtwork.qml`, shared with the Settings tiles). `color`: a plain colour. Since ADR-0040 step 2 the artwork is one of four (`wallpaper.artwork`: the Grassfield hills, Meadow, Field Rows, Ridgeline) in a variant chosen by `wallpaper.artworkVariant` (Time of Day, Automatic, Light, Dark; `WallpaperConfig.artworkVariantFor`): the Grassfield hills follow the phase of the day (`DayPhase`, `TimeOfDay.js`: Dawn, Day, Evening, Night from the time zone, no location) in the appearance's set. A new phase crossfades over `wallpaper.phaseFadeMs` (20 s), waiting while a full-screen window is on that output; a new appearance crossfades over `wallpaper.crossfadeMs`, the bar's tone switching at the midpoint; an output's first wallpaper cuts in. During a crossfade between two artworks the frosted band is on when the tone in effect would fall under 4.5:1 somewhere in the blend (`BarTone.reportArtFade`).
- **One two-slot model for every kind** (`Wallpaper.qml`, `WallpaperSlot.qml`): the artwork, a colour and a picture are all content of a slot, and `WallpaperFeed.display` ({kind, color, url, strip}, replaced only on a SUCCESSFUL outcome: a failure or a pending preparation never changes it) is the only input. Two slots: `shown` (z 1, fully visible until the fade completes) and `incoming` (z 2, opacity 0 until it is ready: the artwork and a colour at once, a picture once its `Image` is `Ready`); the incoming slot crossfades over the outgoing one; a newer request replaces a pending one in the same slot; a failure keeps whatever is on screen; and nothing else sets the opacity of a layer from the requested state (there is no separate colour or artwork layer). So only the outgoing slot, the incoming slot or a blend of the two can show, in every transition (artwork, colour, picture to any other, colour to colour included). A slot keeps its picture while an output mode or scale change reloads it (`retainWhileLoading`). Probes: `tests/visual/wallpaper-transitions.sh` (eight transitions between different contents and a failing file from each kind: every capture must be the outgoing content, the incoming one or a blend; it failed on the layered version for colour to artwork, colour to picture and colour to a failing file), `wallpaper-fade.sh`, `wallpaper-pending.sh`.
- `file` and `folder`: the one-shot helper `grassfield-wallpaper prepare` (`apps/wallpaper-tool`, run as one `Process` per request through `WallpaperJob.qml`, an argument vector, a timeout of `wallpaper.toolTimeoutMs`) parses the user's file and writes a picture of the output's physical size with the fit mode applied (EXIF orientation, sRGB, metadata stripped), plus a sidecar with the menu bar strip statistics and the whole picture's luminance (`image`: mean, 5th and 95th percentile; the backdrop range of the adaptive glass, ADR-0024 G-3; absent from a cache written before 2026-10-26, which then counts as unknown). The shell decodes only that file (two `Image` items, asynchronous, `cache: false`) and crossfades from the old picture (`wallpaper.crossfadeMs`; with Reduce Motion a plain switch, no fade) once the new one is `Ready`; the previous wallpaper stays on any failure. A newer request supersedes the running job (SIGTERM, its answer is ignored). Cache: `$XDG_CACHE_HOME/grassfield/wallpapers/prepared` (dev: `.dev/cache/wallpapers`), 0700, LRU cap 512 MiB.
- `folder`: `list` (one level, supported formats, hidden files skipped, sorted by name), `WallpaperConfig.advance` picks the next picture (no repeat until every picture was shown, stable for a stored seed), the interval timer asks for the next one. The position is kept per display in `$XDG_STATE_HOME/grassfield/wallpaper.json` (runtime state): after a restart the same picture shows while its interval has not elapsed. A bad file is skipped for the session; with every file failing, or an unreachable folder, the current picture stays and the reason goes to `wallpaper-state.json`, which the Settings app shows.
- Menu bar: a wallpaper of any kind reports its tone at 60 % of its crossfade (a picture its strip statistics, a colour its luminance, the artwork its known gradient); `BarTone` picks the tone with the better worst case over the 5th and 95th percentile and switches on the frosted band for that output when neither tone reaches 4.5:1 (menubar.md).
- `online` (ADR-0016 step 2, off by default; Wikimedia Commons Picture of the Day, `wallpaper.online.provider` `commons`): the shell never touches the network. `shell/services/WallpaperOnline.qml` decides when, and one run of `grassfield-wallpaper fetch commons --date <UTC date> --out <cache>/online/commons --lang <en|fr>` does it (curl inside, the helper validates and re-encodes; `latest commons` reads the cache). The feed then treats the newest cached picture like a `file` (`prepare` per output, `label` = its title, the same two-slot crossfade; a new day's picture crossfades in). Rules (pure, `WallpaperConfig.onlineSchedule` and `onlineAfter`, `tests/unit/tst_wallpaper.qml`): the POTD date is the UTC date of ten minutes ago; at most one successful fetch per date (a skipped entry, such as a licence outside the allow-list, also ends the date); the fetch happens at a random time within 6 h after 00:10 UTC, and at once when nothing is cached; failures back off 1 h, 3 h, then the next date (state in `$XDG_STATE_HOME/grassfield/wallpaper-online.json`, runtime state, safe to delete). Only with `Connectivity.fullyConnected` (NetworkManager `Full`, or `Unknown` with a link up; no NetworkManager backend: nothing to ask, the fetch just tries) and not on a metered connection (Quickshell does not expose the flag: one `nmcli -g GENERAL.METERED device show` before each fetch, a metered link is asked about again after an hour; a query that cannot start (no `nmcli`, Quickshell sends no `exited` then) or does not answer within `wallpaper.online`'s `meteredTimeoutMs` (10 s, killed) counts as not metered; a helper that cannot start ends the fetch as a failure with the normal backoff; `tests/shell/wallpaper_online_start_fail.sh` covers the start failures and both timeouts; the real `nmcli` answer could not be run in the sandbox and is NOT VERIFIED). A dev session fetches only from the loopback server named by `GRASSFIELD_ONLINE_BASE_URL` (`http://127.0.0.1:<port>`; the helper refuses it without `GRASSFIELD_DEV=1`) and otherwise never; the dev IPC `wallpaper onlineClock <hours>` moves the scheduler's clock ahead (the date, the slot at 00:10, the backoff and the fetch follow it) and `wallpaper onlineStatus` prints its state. Offline: the last cached picture stays; with nothing cached the artwork shows and `wallpaper-state.json` says `waiting` (Settings: "Waiting for a connection"). The status file also carries an `online` block (`phase`, `failure`, and the sanitized attribution `entry`) that Settings and the desktop menu read; every field is plain text from the helper's sidecar.
- "About This Wallpaper": while an output shows the online picture, or one of the shipped photographs (ADR-0040 step 2c: a picture whose path is an entry of `/usr/share/grassfield/wallpapers/photos/photos.json`, a dev session's `.dev/photos`; `WallpaperState.aboutEntry`, the pure rule `WallpaperConfig.aboutEntryOf`, both only once that output's picture is ready), the desktop (empty space) menu has a second item after a separator. It opens `AttributionCard.qml` with that entry (a `PopupWindow` with a grab, anchored where the menu was, on the frosted material; Title, caption, Author, Source, Licence, Last updated as plain text, a Close button, Esc, Return and Space dismiss it). A photograph is credited as its licence asks (`WallpaperConfig.photoAbout`, the integrator's review of e067f26f): Title is the work's own title (its Commons file name without the extension, not Grassfield's name for it), the Author row reads Credit and gives the author's attribution line as Commons states it, with its copyright notice ("© Vyacheslav Argenberg, CC BY 4.0, via Wikimedia Commons"; the licence's address is the Licence row's link), and a Changes row says "Resized and re-encoded by Grassfield, metadata removed" (THIRD_PARTY.md); it has no caption and no Last updated. Licence compliance (CC BY / BY-SA 4.0 section 3(a)(1)(C), integrator decision 2026-10-22): the licence name is a link to the licence URL and the file page a link to its source (`LinkText`, underlined plain text with a focus ring and the Link accessible role); a link opens on a click or Return (never by itself), only an https address with no white space or hidden character (`WallpaperConfig.linkOf`), as the argument vector `xdg-open <url>` through `Apps.openDetached` (a dev session refuses it by its open policy), and closes the card. The page address reads decoded (`WallpaperConfig.displayUrl`: `File:Name.jpg`, not `File%3AName.jpg`; an escape that would produce a control, bidi or invisible character leaves the address as written). The keyboard state machine sees it as a menu (`menuOpened` and `menuClosed`).
- Dev guard: a dev session accepts only sources under `<repo>/.dev` (also after resolving symlinks, from the helper's `real` path).
- Crossfade: one fixed crossfade of `wallpaper.crossfadeMs` (1000 ms, as macOS crossfades a change); with Reduce Motion a plain switch. No adaptation: the shell does not measure frame times and does not shorten or drop the fade (an earlier version stepped down on "slow frames", but its metric counted animation ticks, not frames: with `--render-timing` the whole shell rendered 6 to 11 frames per fade while each output logged 59 ticks). The incoming picture is always the image on top, it fades in only once it is `Image.Ready` (a change that arrives while the next picture still decodes replaces the pending one and leaves the picture on screen as it is), and the artwork is not drawn while a picture is behind a fade. The menu bar tone follows the new picture once the fade's own progress (the incoming slot's opacity) reaches 60 % (not a timer: a fade is frame-driven) and, when a fade is completed early by the next change or the dev override is cleared mid-fade, the tone of the content that will actually be on screen. Gate P3 (95 % of frames under 16.7 ms, none over 33 ms at fade start) is measured on real hardware with real frame timing: an owner L2 run (`--render-timing`); the nested compositor is the bottleneck there (the Apps panel opens just as slowly) and no nested percentage is claimed. What the nested tests check is what is shown, not how smoothly: `tests/visual/wallpaper-fade.sh` (the dev hooks `wallpaper fadeLength <ms>` and `wallpaper progress <output>` lengthen the fade and read its progress; for five changes in a row a capture inside the fade must lie on the line between the old and the new colour for the progress read just before and after it, `fade_mid.py`, which fails on a hard cut) and `tests/visual/wallpaper-pending.sh` (changes faster than the decode never show the artwork or the bare window; the dev hook `wallpaper loadDelay <ms>` delays the decode).

## Show Desktop and keyboard access (GF-106)
- **Show Desktop** (macOS F11 / Cmd+F3; Grassfield: **Super+F3**, `qs ipc call windows showDesktop`, listed in Settings > Keyboard): moves the windows of **every display's** current Space aside (to `special:desktop`, a workspace nobody toggles; one record per display) and gives the desktop icons the keyboard (`DesktopState.focusRequested` -> event `request` of `KeyboardFocus.js`: the kicker runs even under the compositor policy, because no click will come). The window positions are read again from Hyprland first (the press waits at most `showDesktop.refreshMs`). Minimized and hidden windows are left alone. With Stages on the press does nothing at all (a stage cannot be rebuilt window by window, stages.md ST8/ST9).
- Ends, and every window goes back to its own Space in its tiling order (top-to-bottom then left-to-right): pressing it again, switching Space, a new window opening, activating a window (Dock, switcher, Overview). An app activating a parked window (`focus_on_activate` shows `special:desktop` over the screen) ends it too: the event is `activespecial` naming `special:desktop` (our own parking is silent and never raises it; the focus is no evidence, a parked window can keep it). Which window was activated comes in two orders, both recorded from Hyprland 0.56.2 (`tests/unit/fixtures/showdesktop/`): a real client request (xdg-activation, `focus_on_activate`: `CWindow::activate`) posts `activewindowv2 <A>` BEFORE `activespecial`; the focus dispatcher (`hl.dsp.focus`) posts `activespecial` first and `activewindowv2 <A>` after it. The flow takes the window named by the `activewindowv2` right before the workspace event (at most two focus or workspace events earlier: events are counted, there is no clock anywhere in the flow), or the first one named after it and before the shell's own hide or first move; whatever follows is a consequence of the ending (the first window that comes back takes the focus) and is ignored. The focus is asked for after the windows went back, never for a window that is still parked (Hyprland would show the workspace again: the flow looks again a few times, then leaves it), and never for a window that is neither one it sent back nor parked. Hyprland posts both event forms (`activespecial`, `activespecialv2`) for one change: the second form of a show that was handled is its echo, matched to the event (not to a time), so a second activation right behind the first is handled too; the workspace is hidden FIRST (by state, from the tracked `activespecial` events, never by a blind toggle that would open it), then every window goes back, and the window that was activated keeps the focus. Every ending leaves the parking workspace hidden, also an ending that ran before the workspace event arrived. Known limit: Hyprland has already shown the workspace and starts its `specialWorkspace` animation (`config/hypr/grassfield/looknfeel.lua`, a fade, global: Hyprland has no per-workspace animation) before the shell can react, so the parked windows can be seen for the few milliseconds up to the shell's hide; the shell removes the rest (nothing stays shown, no second toggle), it cannot remove that first frame. A shorter or instant fade for that one workspace needs a Hyprland setting the shell does not own (proposal for the config owner). A parked window that no record owns (the record file was corrupt, from a future version, or could not be written, and the shell restarted) is brought back the same way the moment an app or the Dock activates it: the workspace is hidden, the window moves to the Space of the focused display and gets the focus (macOS: a window you activate is always shown). Restoring a minimized window (Dock tile, Overview) ends it first, and the second press ends it with Stages on too. The window to send back is decided by one rule everywhere (ending, verify, crash recovery): it is on the parking workspace now; a window the user moved out by hand stays where the user put it. A new capture finishes the verify of the previous ending synchronously: what is still parked stays parked (not moved back, so it is not on screen during the new Show Desktop) and joins the new records (three quick presses never strand a window); a verify that still finds windows parked after its last try gives them a record again. Crash recovery keeps the record until every listed window is back or known closed, waits for the window list (bounded, `showDesktop.recoverTries`), and sends stragglers back again (`ShowDesktop.recoverStep`); at the bound the record stays on disk while a window is still parked. **Focus follows what ended it** (macOS): a Space switch keeps the new Space and its focus, a new or activated window keeps the focus, and only the second press, on the Space it was pressed on, refocuses the window that had it. Every other ending issues no focus request at all (it would make Hyprland switch back to the old Space). The shell's own moves are told apart from the user's by what the events name (the parking workspace, the parked windows), not by timing. The records (`ShowDesktop.js`) are persisted in `$XDG_STATE_HOME/grassfield/show-desktop.json` (0600) on every change, so a restarted or crashed shell puts the windows back about `showDesktop.recoverMs` after start, focusing nothing: nothing stays hidden. All of it is a pure reducer, `shell/platform/ShowDesktopFlow.js` (events, timers, presses, the file read, the screens changing and the shell's own activations in; the dispatches in order, the timers, the record file out), run by `shell/platform/showdesktop/ShowDesktopController.qml` (listens to the Hyprland events, reads the context, runs the dispatches in order, the timers and the record file; the window list is only built for the events that need it); `Compositor.qml` only gives the controller the real Hyprland and tells it how to read the Spaces and where to send requests. Tests: `tests/unit/tst_showdesktop.qml` (the pure rules), `tst_showdesktopflow.qml` (the flow against a model of Hyprland: both activation orders, three quick presses, a concurrent ending, stragglers, the verify bound, the recovery bound), `tst_showdesktopreplay.qml` (the recorded sequences), `tst_showdesktopglue.qml` (the real controller offscreen with a fake event source and dispatcher: events forwarded, dispatches in order, context, record file, timers), `tests/shell/show_desktop_wiring.sh` (what Compositor.qml hands the controller, no clock), `tests/shell/ux_mutants.sh` (mutants of these rules and of the glue, all killed); every flow and replay test ends by checking that `special:desktop` is not left shown; the fixtures are made by `tests/shell/show_desktop_record.sh --write`, which without the flag is also the nested test that notices Hyprland changing the two event orders; nested: `tests/shell/show_desktop_nested.sh` (asserts the Space and the focus after the second press, a Space switch, a new window, a switcher activation, three quick presses, the focus dispatcher on a parked window, a real xdg-activation by `tests/tools/xdgact` (a window that activates itself while parked), and the crash recovery: the shell is restarted while the windows are parked and they all come back).
- **A display going away** (monitor unplugged, lid closed with an external display; macOS: the windows move to a remaining display and the shell keeps working, no restart): a screen is kept as a name and looked up in the live list when used (`shell/platform/ScreenChoice.js`, functions `gone` and `replacement`: the screen to move to is computed from the live names and the focus inside each handler, never from a binding of the same change; `tests/unit/tst_screenchoice.qml`): the open popup (`Popups`), the switcher session, the Notifications panel and the Apps panel move to a live screen when theirs goes (`Quickshell.onScreensChanged`), and the bindings of every per-screen window tolerate the null screen they read while it is torn down (no "Cannot read property of null" in the log). Show Desktop ends when a display of its records is gone and the parked windows come back (the Space they were on moves to a remaining display with Hyprland); widgets and desktop icons placed on a removed display keep their saved place until it returns. `tests/shell/display_unplug_nested.sh` removes a headless output twice (and works after the first output of the session was removed too): popup, parked windows, switcher, Show Desktop, a new popup and a notification all keep working, and the log has no null-screen error.
- Keyboard inside the desktop: arrows move the selection, **Tab / Shift+Tab** walk the icons in visual order and wrap (`IconsLogic.cycle`); a widget's context menu offers **Move Left/Right/Up/Down** (desktop, one cell, never over a neighbour) and **Move Up/Down** (Notifications panel); the menu itself opens with the pointer, as on macOS.

## Keyboard focus (ADR-0012, owner decision 2026-10-17: the macOS model)
The desktop belongs to the shell like Finder belongs to macOS: clicking it activates it, hovering never does. Hyprland decides who holds the keyboard; the shell only reacts to its own surface (`KeyboardFocus.js`, pure, `tests/unit/tst_desktopfocus.qml`; host `DesktopIcons.qml`). Spike evidence (nested Hyprland 0.56.2, with and without the plugin, identical): `docs/decisions/ADR-0012-desktop-focus-model.md`.

Rules:
1. The desktop surface (`grassfield-desktop-icons`) has keyboard interactivity `None` until a left press on it; then `OnDemand` ("armed"). Hover, windows opening or closing and the pointer on another output change nothing. Hyprland gives an OnDemand surface the keyboard only at the next pointer motion, so the press also maps a transient 1x1 transparent Background surface (`grassfield-desktop-kicker`, keyboard None) for `Tokens.desktopIconFocusKickMs`: mapping and unmapping it makes Hyprland re-evaluate and grant the keyboard (measured 60 to 180 ms) without any motion. When the keyboard is not granted within `Tokens.desktopIconFocusArmMs` (the pointer is over a window), the surface goes back to `None` (never OnDemand while idle: a permanent OnDemand would take the keyboard on hover).
2. "Held" = the surface window is active (`Window.active`, wl_keyboard enter; `activeFocus` is not usable: `forceActiveFocus` sets it on an inactive window). Only then the desktop keyboard actions run (`IconsView.keysActive`). Losing the keyboard (Hyprland focused a window after a click on it) goes back to `None`.
3. The pointer leaving the surface (onto a window, the other output, the menu bar, the Dock, a widget) also goes back to `None`: Hyprland ignores a click on the window it already counts as active, so without this a desktop that had the keyboard would keep it after a click on that window. The keyboard returns to Hyprland's last window at once.
4. Context menu: a `PopupWindow` with `grabFocus`, anchored to the desktop surface; the surface stays OnDemand while it is open. Esc or an item closes it and the keyboard is back on the desktop (20 to 80 ms later). A click elsewhere (window, other output) dismisses it and is swallowed by the compositor; the keyboard also goes back to the desktop, even if the pointer is over a window, so after an outside dismissal the surface drops to `None` for one kick interval and arms again: it gets the keyboard back only if Hyprland finds the pointer on the bare desktop; otherwise the keyboard is with Hyprland's last window and typing goes there.
5. Rename and the actions: see "Interaction" above.

Works with the pointer regardless: selection, double click to open, drag and drop in and out, Move to Trash from the menu.

Residual limits (measured, not fixed):
- Keys typed within about 50 ms of the menu closing (Esc, an item) are dropped by the closing popup, never misdelivered: with `keys.sh` started right after the Esc, 2 to 8 of 10 reached the desktop; with 50 ms or more between, 10 of 10 (plugin and no plugin, 0 keys ever reached a foot).
- After an outside-dismissal click, or a pointer move onto a window, the keys go to Hyprland's last active window, not the desktop (deviation from macOS, where the click would keep Finder active). One click on the desktop gives it the keyboard again.
- Hyprland re-evaluates focus only on pointer motion events: a pointer that jumps from the menu straight onto a window without a single motion over the bare desktop (a virtual pointer does this; a real one does not) leaves the desktop holding the keyboard under that window until the pointer moves over the desktop again.
- While the desktop holds the keyboard the pointer must leave and re-enter its surface to be reported again; widgets, the menu bar and the Dock count as leaving.
- Ctrl/Meta+O (open) was not exercised in the nested session (it would start an application).

Dev: `scripts/dev/shell-run.sh` seeds `lock.idleMinutes: 0` in the dev config when the key is absent, so nested sessions never idle-lock.

## Compositor focus policy (capability `desktop-focus`, ADR-0012 amendment 2026-10-18)
What the shell cannot do alone (review of 354cf71): Hyprland 0.56.2 ignores a click on the window it still counts as
focused while the desktop holds the keyboard; it grants an OnDemand surface the keyboard only at the next pointer motion
(hence the kicker); and the shell's pointer-leave drop sends keys to a window the user did not click. grassfield-compositor
(plugin 0.5.0-df, `compositor/src/DesktopFocus.cpp`, decision logic `compositor/src/core/DesktopFocus.*`) enforces the
macOS click-to-focus model instead. Contract (exact):

1. **Detection.** The feature is present when the latest `capabilities` event lists `desktop-focus`
   (`Capabilities.has("desktop-focus")`). Policy v2 (plugin 0.6.0, 2026-10-18) is advertised as `desktop-focus-v2`,
   always together with `desktop-focus`: the file-changing desktop keys need `desktop-focus-v2` (shell main 23caeab;
   the first policy misread a click without motion after the menu closed). The plugin posts a capabilities event with an empty list when it unloads
   (`{"v":"gfc/1","type":"capabilities","features":[]}`): every feature is gone at that moment, the shell must react to
   any capabilities event, not only to the first one.
2. **Surface identity.** The plugin matches the layer namespace **`grassfield-desktop-icons`** exactly, on any output
   and any layer. Do not rename it without changing `kDesktopNamespace` (plugin) in the same change. Its xdg_popups (the
   context menu) are recognised as the desktop's popups.
3. **What the shell keeps doing (with or without the plugin):** keyboard interactivity `None` while idle; `OnDemand` on a
   left press on the desktop; back to `None` when the surface loses the keyboard (`Window.active` false after it was
   true); the arm timeout (`Tokens.desktopIconFocusArmMs`) back to `None` if the keyboard was not granted; the context menu
   as a `PopupWindow` with `grabFocus`; desktop keyboard actions only while `Window.active`.
4. **What the shell drops when `desktop-focus` is present:** the kicker surface (`grassfield-desktop-kicker`) and the
   drop to `None` on pointer leave (rule 3 of "Keyboard focus"). The outside-dismissed menu re-arm (rule 4) is not
   needed either: after an outside click the keyboard is back on the desktop, and the next click on any window gives that
   window the keyboard. `IconsView.fileKeyActions` (Return/F2 rename, Ctrl/Meta+O open, Ctrl+Backspace trash) may be
   enabled. When the feature is absent or withdrawn: kicker and pointer-leave drop back on, `fileKeyActions` off.
5. **What the plugin guarantees** (pointer button presses only; hover never moves the keyboard; button events are
   observed, never cancelled):
   - a press (any button) on a normal window (its surface, a subsurface or its Grassfield titlebar) while the desktop
     surface (any output) holds the keyboard gives that window the keyboard, also when it is Hyprland's focused window,
     through Hyprland's own focus rules only (v2: a window Hyprland refuses, e.g. a `no_focus` rule or a modal child, does
     not get it: the keyboard stays where it is);
   - v2: the press target is what lies under the cursor when Hyprland's pointer focus is missing or stale (a click
     without pointer motion right after the menu closed, while the pointer rests on a window);
   - a left press on the desktop surface gives it the keyboard at once if it is `on_demand`, else on its first
     `on_demand` commit within 1000 ms after the press (no pointer motion needed); v2: that pending grant is dropped when
     anything else moves the keyboard first (a key binding or dispatch, a new window, a workspace switch);
   - presses on other Grassfield layers (Dock, menu bar, widgets, any `grassfield-*` namespace), on popups (the desktop's
     menu included: the grab decides) and anything while a keyboard grab, an Exclusive layer or the session lock is active
     change nothing.
6. **Timing.** The grant happens on the shell's `on_demand` commit (one frame after the press). Keys typed before that
   commit go to the previous holder; measured: keys sent right after the click (no motion) reached the desktop in 5/5
   rounds (`tests/compositor/desktop_focus.sh`, case 2).

Evidence (nested Hyprland 0.56.2, plugin 0.5.0-df, two outputs, stand-in desktop with the behaviour of item 3/4,
`tests/compositor/desktop_focus.sh`): 21/21 checks PASS: (1) desktop focused, click the last active foot: the foot gets
the keys; (2) click the desktop, type at once: the desktop 5/5; (3) hover the Dock, the menu bar, a window, presses on the
Dock and the menu bar: the desktop keeps the keys; (4) the last active foot on the other output gets the keys; (6) the
menu grab keeps keys, Esc returns them, an outside click is swallowed and the next click on that foot gives it the keys;
(5) unload while the desktop is focused: Hyprland alive, empty capabilities posted, keys still reach the desktop, a click
on another foot works, reload restores the policy. `desktop_focus.sh baseline` (same presses, plugin unloaded) reproduces
the review defects: (1) and (4) keys reach the desktop, (2) 0/5 (keys reach the previous window).
Policy v2 (plugin 0.6.0, 2026-10-18): 26/26 PASS, adding (8) menu open, pointer onto the last active foot, Esc, click
without motion: the foot gets the keys, and (7) a slow `on_demand` commit (700 ms) loses to a focus dispatch or a new
window made in the meantime, and still grants the desktop without interference. The previous build (e066a19) fails (8)
(keys to the desktop), (7a) (the late commit took the keyboard from the window a focus dispatch had just focused) and
(7b) (it took it from a window that had just mapped); see ADR-0012.

Limits: touch and tablet taps are not covered (pointer buttons only); a press on a window's border (outside its titlebar
and surface) is left to Hyprland.

### Shell side of the policy (2026-10-18)
`KeyboardFocus.js` takes the policy as an argument (`next(state, event, policy)`, `kicking`, `rearmAfter`, `fileKeyActions`);
`DesktopIcons.qml` binds it to `Capabilities.has("desktop-focus")` live (kicker, pointer-leave drop and `fileKeyActions` follow;
withdrawing it while the desktop holds the keyboard and the pointer is elsewhere drops to None at once). The menu bar shows the
desktop's name ("Desktop", `DesktopState.holdsKeyboard`) while the desktop or its context menu holds the keyboard.
Nested evidence (plugin loaded, GF-REF): menu opened on an icon, pointer moved onto foot, Esc, small pointer motion, click, typing
and Return/Ctrl+Backspace reached foot only; click on the desktop then Ctrl+A at once selects all; hovering the Dock and the
menu bar keeps the keys on the desktop; click on foot on the other output gets the keys; Ctrl+Backspace on a selected file moved
it to `.dev/apps-home/data/Trash` (owner's `~/.local/share/Trash/info` mtime unchanged); after `just plugin-unload` the menu hints
and file keys are off live. Limit found: a click with the pointer perfectly still after a popup grab ended (no motion since
the grab) is classified "none" by the plugin and Hyprland, the keys stay on the desktop.

Plugin unload (R13 review): an empty capabilities event now means the plugin is gone (`Capabilities.pluginPresent` false,
`CapabilityEvent.js`, `tests/unit/tst_capabilities.qml`): the degraded notice is posted once (`shell.qml` `syncDegradedNotice`,

mode itself starts at the 1.5 s timeout, but a loaded plugin can answer seconds later at a start (the slow hellos of
ff5f888), and the notice must not show for a moment then (`tests/visual/degraded-notice.sh`).


## Folder colours
Folder icons on the desktop follow `icons.folderColor` and the folder's own look (colour and symbol set in Files, Customize Folder): `DesktopIcon` draws a folder through `FolderIcon`; `DesktopFiles` reads the attribute `user.grassfield.folder` of the listed folders with one `getfattr` process per listing change and the per-user store `folder-styles.json` through a watched `FileView` (docs/specs/files.md, Folder colours and Customize Folder).
